## November 21, 2026: require Okta sign-in

- **Require Okta sign-in.** In **Settings, Sign-in rules**, the owner can make the team's Okta (on a self-hosted install, the organization's) the only way in. It turns on only when Okta is on, every email domain is verified, and the owner's own session signed in with that Okta, so a broken setup can't lock the team out. While it is on, password, Google, GitHub and Microsoft sign-in, switching into the team and connecting apps from other sessions are refused with a message that names the team, and sessions that didn't start with Okta end at once; your other teams are not affected. The page lists who hasn't linked Okta yet and warns with that list. New members accept their invite with Okta when Okta's verified email matches the invite. If Okta breaks, the owner can still sign in with their password and two-factor code; each such sign-in is logged and listed on the page. API keys and CI tokens keep working. ([coderhelm-platform pull requests](https://github.com/CoderHelm/coderhelm-platform/pulls?q=is%3Apr+require+okta), [dashboard #465](https://github.com/CoderHelm/coderhelm/pull/465))

## November 19, 2026: sign in with Microsoft and Okta

- **Sign in with Microsoft.** Work, school and personal Microsoft accounts can sign in, on CoderHelm's cloud and on self-hosted installs that add their own Entra app registration. CoderHelm checks Microsoft's signature, the account's own tenant, the nonce and the expiry, and takes the email only when Microsoft says its domain is verified. The button shows only where it is set up. ([#793](https://github.com/CoderHelm/coderhelm-platform/pull/793), [dashboard #463](https://github.com/CoderHelm/coderhelm/pull/463))
- **Sign in with your team's Okta.** In **Settings, Sign-in rules**, an admin enters the Okta domain, client ID and secret (kept encrypted), copies CoderHelm's sign-in redirect address into Okta, runs **Test sign-in**, and on CoderHelm's cloud proves each email domain with a DNS TXT record before turning it on. Each member then links their own Okta account in **Settings, Security**, from a sign-in they started another way, and chooses **Continue with Okta** with their work email after that. Okta signs in only the member who linked that Okta account, never anyone matched by email. On CoderHelm's cloud the session stays on that team; on a self-hosted install only the owner can turn Okta on. Two-factor sign-in is asked for after Microsoft and Okta, as after Google and GitHub. ([#793](https://github.com/CoderHelm/coderhelm-platform/pull/793), [dashboard #463](https://github.com/CoderHelm/coderhelm/pull/463))

## November 19, 2026: read-only permissions arrive with the release

- **New read-only permissions arrive with the release, with no alert.** On an install's own AWS account, each release update now adds that release's read-only permissions to the CoderHelmLogReader role by itself, with the AWS switches as the install has them, so nobody has to update anything and the AWS page says it updates with the release. Other AWS accounts show the update quietly on the AWS page with its one-click link; CoderHelm no longer sends a notification about read-only permissions. Existing installs update their access stack once to get this. ([#789](https://github.com/CoderHelm/coderhelm-platform/pull/789), [dashboard #461](https://github.com/CoderHelm/coderhelm/pull/461))
- **A ticket that keeps failing stops restarting by itself.** After 3 failed runs in a row, a ticket event that leaves the ticket unchanged starts no further run. A content change, Retry, a command, or a person adding the trigger label or assigning CoderHelm on GitHub or Jira still starts one. ([#773](https://github.com/CoderHelm/coderhelm-platform/pull/773))

## November 19, 2026: ticket lookups for moved teams, merged work never rebuilt

- **Ticket lookups in chat for teams that run their own CoderHelm.** When a team moved from CoderHelm's cloud to its own install, the Jira app could no longer send CoderHelm its new links, so chat couldn't look up tickets. Those registrations are now accepted through the team's install link, checked against the site's secret, and the install copies the new links by itself. When the Jira app refuses a request, CoderHelm now records its reason. ([#788](https://github.com/CoderHelm/coderhelm-platform/pull/788))
- **A deploy label's workflow is part of the preview.** A pull request no longer leaves draft while the workflow its deploy label starts is still running. The description quotes how that workflow ended, a backend-only change still has a time limit on its wait, and the merge gate never adds a deploy label again on a commit the preview already ran. ([#705](https://github.com/CoderHelm/coderhelm-platform/pull/705))
- **No second run on a ticket whose pull request already merged.** Before a run builds anything, CoderHelm checks the ticket's merged pull requests the same way it checks open ones: work that is already merged is not rebuilt, and work that is partly merged builds only the rest. An answer on the ticket keeps that check. ([#706](https://github.com/CoderHelm/coderhelm-platform/pull/706))
- **Before and After from the end-to-end screenshots.** CoderHelm's pull requests show a Before and After pair from the screenshots their end-to-end run already took, read from the test reports CoderHelm already parses. ([#707](https://github.com/CoderHelm/coderhelm-platform/pull/707))

## November 18, 2026: chat knows Jira is connected

- **Chat knows Jira is connected, and missing Jira links repair themselves.** Chat, the Integrations page and runs now share one check for whether Jira is connected, so chat never says Jira isn't connected when it is. When the Jira app gains a link in an update, or a site is missing one, CoderHelm asks the app to send its links again and existing installs copy them on their own, with nobody re-saving settings. Until a link is back, chat names exactly what is missing and answers from the tickets CoderHelm's runs already know. ([#786](https://github.com/CoderHelm/coderhelm-platform/pull/786))

## November 18, 2026: approved pull requests merge, conflicts and all

- **Approved pull requests merge, conflicts and all.** When a pull request CoderHelm is set to merge falls behind or conflicts with its base, CoderHelm merges the base in itself, checks the pull request's own change is unchanged, reviews the new commit and carries on. An approval GitHub still counts is counted, the merge is checked again every 15 minutes while it waits, and a wait always says what is missing: whose approval, dismissed by which commit, and how many the branch needs. ([#783](https://github.com/CoderHelm/coderhelm-platform/pull/783))

## November 18, 2026: a code map per repository, criteria traced to proof, and reads as your own role

- **A code map per repository, kept current.** CoderHelm keeps a summary of each repository: architecture, stack, how to build and test, conventions and how its parts depend on each other, each part stamped with the commit it describes. Only the parts a change touches are rebuilt, and the planner and coder start from it instead of exploring the repository again. ([#780](https://github.com/CoderHelm/coderhelm-platform/pull/780))
- **Every criterion traced to its code, tests and proof.** The pull request description shows each acceptance criterion with the code changed for it, the tests that cover it and the proof result, rebuilt on every push. A criterion with no code, test or proof starts a fix round like any other open item. ([#780](https://github.com/CoderHelm/coderhelm-platform/pull/780))
- **Checklists for risky changes.** A plan that touches infrastructure, CI, permissions, data, performance or monitoring answers a short checklist for that area (rollout and rollback, environments, permissions, cost, limits, monitoring, migration safety, compatibility), each answer with its source. ([#780](https://github.com/CoderHelm/coderhelm-platform/pull/780))
- **An approval after a merge from the base keeps its review.** When a pull request's own change is unchanged and CoderHelm approves it again, the approval carries the earlier review in full, and tidying older reviews never hides the review an approval rests on. ([#781](https://github.com/CoderHelm/coderhelm-platform/pull/781))
- **Reads of your AWS account always use your read-only role.** On an install in the same account it reads, CoderHelm now reads logs, metrics and firewall data as CoderHelmLogReader too, so a run and its access check can't disagree, and a run never waits twice for the same access. ([#782](https://github.com/CoderHelm/coderhelm-platform/pull/782))

## November 18, 2026: one run per ticket, runs that finish, and tickets proven on the preview

- **One ticket, one run.** Every trigger, from Jira, a GitHub issue, a plan task or an alert, claims the ticket before anything starts, and an issue CoderHelm opens for a ticket points back to it. A second trigger for a ticket already being worked starts nothing, so one ticket gets one pull request. ([#778](https://github.com/CoderHelm/coderhelm-platform/pull/778))
- **Runs finish instead of handing work back.** The fixed limit on continuations is gone: each continuation names what it still has to close, and the run goes on while it closes something. When progress stops, the pull request ships with what is left listed, and a red check afterwards still starts a fix round. ([#778](https://github.com/CoderHelm/coderhelm-platform/pull/778))
- **The ticket is proven on the preview.** A criterion about what the server sends, such as content without JavaScript, is checked against the preview's own HTML and the base's before the pull request is ready. A test that can't run because its install failed is reported as not run, never as failing, and a test that fails or proves nothing holds the draft. ([#778](https://github.com/CoderHelm/coderhelm-platform/pull/778))
- **Sharper plans.** Plan checks list each gap once, never put what the ticket asks for out of scope, and treat a broken value with a working one beside it in our own pipeline as a code fix, not a change for someone else. ([#778](https://github.com/CoderHelm/coderhelm-platform/pull/778))

## November 18, 2026: runtime vulnerabilities, and alarm runs that read the firewall themselves

- **Vulnerabilities in the language runtime, not only its libraries.** CoderHelm reads which Java (and Node, Python and Go) a team runs from Dockerfile images, version files, build settings, CI setup steps and Lambda declarations, and which Java packages are installed on its servers. Java versions are matched against the runtime's own advisories, so a JDK bug like CVE-2026-114938 becomes a finding: a pull request to the fixed version when one is published, otherwise a rebuild or the advisory's mitigation flag. When a bug needs a particular CPU, each server's instance type says whether it is exposed. ([#775](https://github.com/CoderHelm/coderhelm-platform/pull/775))
- **Alarm runs read the firewall data themselves.** Runs read any CloudWatch metric the AWS role allows, WAF included, and read a WAF rule's sampled requests and log files directly, without Athena. A run whose only blocker is a read the role doesn't allow yet waits, shows one setup item, and starts again by itself once the role allows it, instead of handing the work to a person. ([#776](https://github.com/CoderHelm/coderhelm-platform/pull/776), [#454](https://github.com/CoderHelm/coderhelm/pull/454))

## November 18, 2026: previews found wherever your host publishes them

- **Previews are found wherever they are published.** CoderHelm reads the head commit's deployments, deploy statuses, preview checks and bot comments, then the description and your address template. Only what belongs to the head commit counts first, and the changed app's preview is picked in a monorepo. It waits at most an hour for a preview that is still building, and reports a failed one with where it read it. ([#772](https://github.com/CoderHelm/coderhelm-platform/pull/772))
- **Protected previews.** **Settings**, **Repositories**, **Preview access** holds the preview's address when nothing publishes it, and one sealed secret: a header, a query parameter or a password. CoderHelm sends that secret only to the preview's own host. Details: [Pull request previews](/concepts/previews). ([#772](https://github.com/CoderHelm/coderhelm-platform/pull/772))

## November 17, 2026: tests that actually run, and plan dependents released by their own ticket

- **Tests actually run.** Workspace packages install from the workspace root with CI's own job, cached install and pinned versions, and a failed install says why. Test runs that don't fit in a step get a fresh step of their own instead of being skipped, more CI test commands are read, and the run page and pull request say how many tests ran with and without the change. ([#769](https://github.com/CoderHelm/coderhelm-platform/pull/769))
- **A merged plan task releases its own dependents.** The task is found through its ticket's plan link, or by the ticket recorded on its own task row, so a Jira task releases its dependents and an issue number in another repository can never release the wrong ones. ([#719](https://github.com/CoderHelm/coderhelm-platform/pull/719))

## November 17, 2026: criteria proven both ways, a reviewer that converges, reproduce first

- **Each ticket criterion is proven both ways.** The plan maps every acceptance criterion to an end-to-end test of the page it names, and before the pull request is called done each test is run on staging (it must fail) and on the preview (it must pass); a test that passes on both goes back to the coder. Near-identical helpers added in one change are caught. ([#766](https://github.com/CoderHelm/coderhelm-platform/pull/766))
- **A reviewer that converges.** Each finding gets one verdict; everything is raised in the first review; a blocking finding must name its file, line, the existing code and the change wanted; a finding doesn't move to the next file, ask for the opposite of an earlier request, or block after CoderHelm's own fix rounds deferred it; a person's answer is never called out of scope. Once the criteria are proven and CI is green, the review approves with notes, and the posted review follows every new commit. ([#765](https://github.com/CoderHelm/coderhelm-platform/pull/765))
- **Reproduce before planning.** A bug plan quotes the ticket's real names, the command run on the base and its output, and the line where the code goes wrong, and fixes the mechanism that line belongs to. A change much wider than the records the ticket names is flagged, tests must fail on the base before they count, questions are answered by a lookup first, and a person's answer moves work into scope. ([#768](https://github.com/CoderHelm/coderhelm-platform/pull/768))
- **New AWS reads reach every team.** The read-only role is one template with named read groups shipped with each release; when a team's role is older than the release or lacks a read a feature needs, Settings shows one item with a one-click CloudFormation update, and runs carry on instead of asking. ([#764](https://github.com/CoderHelm/coderhelm-platform/pull/764))

## November 17, 2026: checked pushes, scope held, and tidy reviews

- **A fix is pushed only after its own checks pass.** Before every push CoderHelm runs the type check, lint and tests of the package that owns each changed file, the whole unit suite when shared code changes. A red result is not pushed; a check that can't run is marked unverified in the commit. Commit messages are checked against their diff, a revert takes its tests with it, and after two fixes for the same failing test CoderHelm stops and names the test and its error instead of rolling the branch back. ([#760](https://github.com/CoderHelm/coderhelm-platform/pull/760))
- **Scope is decided once and held.** Every plan says what is out of scope and why; the run records it before any code, and code or tests brought back against it are fixed in the next round unless a criterion or a person's answer moves it. Open product questions become decided defaults, and the description is rebuilt from the head on every push: no stale history, no claims the diff contradicts, and a length that fits the change. ([#762](https://github.com/CoderHelm/coderhelm-platform/pull/762))
- **Reviews and threads stay tidy.** After a push, merge or close, CoderHelm's older reviews shrink to one line, its threads whose finding no longer holds (checks now pass, the code is gone) are resolved and hidden, and new reviews show only the verdict and what holds the merge, with the rest folded. A person's review or thread is never touched. ([#761](https://github.com/CoderHelm/coderhelm-platform/pull/761))

## November 17, 2026: red checks reproduced first, and a reviewer that reads only the change

- **A red check is reproduced before it is blamed or reverted.** When an end-to-end test fails, CoderHelm runs it against staging and the preview and records both. It reverts its own work only when that record shows the change caused the failure, and when the test fails on staging too it fixes the test on the branch. The fixer reads the failure's test name, error and screenshot, and the description drops "CI is failing" and revert lines once they stop being true. ([#754](https://github.com/CoderHelm/coderhelm-platform/pull/754))
- **The reviewer reads only the pull request's own change.** After main is merged in, files the merge brought are no longer reviewed or called unrelated. A passing end-to-end run whose report shows a page's test ids counts as a probe, and when one is missing the reviewer probes the page itself instead of blocking. Failing checks are compared test by test with main before anything is called pre-existing, and a review that asks for a test sends it to the coder as work, with how to test scripts and CI. ([#758](https://github.com/CoderHelm/coderhelm-platform/pull/758))

## November 17, 2026: tests built from the live page, and WAF alarms that read their evidence

- **Tests against outside pages are built from the live page.** Before CoderHelm writes or keeps a selector for a vendor page, it probes that page and records each test id's state and what clicking it brings up, and the PR quotes the probe. A test branch that no recorded run has taken is labelled unverified until the page can take it and it has run. Changes that only reformat a file are put back. ([#755](https://github.com/CoderHelm/coderhelm-platform/pull/755))

When the role is missing those reads, the install shows one setup item with a one-line update, and the run carries on instead of asking a question. ([#757](https://github.com/CoderHelm/coderhelm-platform/pull/757))

## November 17, 2026: the coder makes the smallest change

A plan or diff is sent back when it adds a structure next to an existing one, deletes or replaces stored data the ticket never asked to touch, adds reporting nobody asked for, or changes a test to match an outside page when the product should change.
