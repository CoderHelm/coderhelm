A run is carried out by several agents, each a Claude model with its own instructions and tools.

| Agent | Does | Model setting |
| --- | --- | --- |
| **Planner** | Triage, the plan, and plan chat. Reads code, the code graph, memories, skills and connections; never writes. | Planning & reviews |
| **Coder** | Writes the change, runs the build and tests in the sandbox, fixes CI failures and answers feedback. | Writing code |
| **Reviewer** | Reviews CoderHelm's own pull requests and your team's (see [The PR reviewer](/getting-started/reviewer)). | Planning & reviews |
| **Writer** | Pull request descriptions, replies to comments, and release notes. | Planning & reviews |

Choose the models on **AI Models** (admins only). The models on offer are Claude Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 4.5, plus older models for teams that pinned one. A model that Anthropic retires runs as its replacement automatically.

## What agents can touch

- **Your code**: read through the GitHub App. Changes are pushed only to `coderhelm/` branches and arrive as pull requests.
- **The sandbox**: builds, linters and tests run in an isolated build environment with no credentials and no access to your systems. Its commands and network are limited by your [agent permissions](/concepts/agent-permissions#the-sandbox).
- **Your data**: only through [data sources](/concepts/data-sources) and [team tools](/concepts/skills#team-tools), which are read-only.
- **Outside tools**: only through [connections](/concepts/connections) an admin switched on.

Before each call, every agent asks your team's [agent permissions](/concepts/agent-permissions). The answer is allow, ask or deny. An ask waits for a person to approve it.

## Team agents

Your team can add its own agents, written as Markdown files in a skill repo. A team agent is a specialist the main agents can ask, for example "the payments expert". Team agents answer questions with read-only tools; they never write code. See [Skills](/concepts/skills#agents).

## Instructions

Besides skills, admins can set plain-text instructions in **Settings**, for the whole team or one repository: general instructions, rules, the voice for PR descriptions and comments, and git conventions (branch, commit and pull request title templates).

## What CoderHelm learned about a repository

When a repository is turned on, CoderHelm reads it and writes a short guide for its agents: what the repository does, its stack and folders, how it builds and tests, its CI, and the review and contribution guidance it states. You can read it in **Settings**, **Conventions**, under one repository.

The guide refreshes by itself:

- **After changes on the default branch** to the files it is read from: manifests such as `package.json`, `Cargo.toml` or `go.mod`, CI workflows, the README, `AGENTS.md`, `CLAUDE.md`, contribution and review guidelines, Cursor rules, the pull request template, lint, format and test config, or a top-level folder added or removed. CoderHelm waits until 30 minutes after the last such push, so a run of merges causes one refresh, and refreshes each repository at most once a day.
- **When it is more than 30 days old** and the default branch has new commits since.

The page says when and why it was last written, for example "Updated automatically on November 9, 2026 after changes to package.json and CI". A refresh uses your team's model and counts toward your [token limits](/concepts/token-limits); a team over its limit is skipped until the limit allows. Your own repository instructions are kept apart and read on every refresh, so nothing you wrote there is lost. A guide that someone saved by hand through the API is never replaced by itself: it is marked out of date, with a button to write it again.
