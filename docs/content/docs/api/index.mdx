The CoderHelm API lets your scripts, CI jobs and internal tools start and follow CoderHelm's work:

- list runs, follow one as it works, and retry or cancel it
- create a plan with tasks and run it
- read the reviewer's pull request reviews and their findings
- check the team's token usage against its limits
- upload test reports from CI and read which tests are quarantined

Every endpoint is listed under **Reference** in the sidebar, grouped by resource, with its parameters, request and response fields, errors, and example requests in cURL, TypeScript and Python.

## Base URL

```txt
https://api.coderhelm.com
```

All requests use HTTPS. Bodies are JSON (`Content-Type: application/json`), except the CI report upload, which takes the report file as it is.

## Your first request

<Steps>
<Step>

### Create a key

An admin opens **Settings**, then **API keys**, and chooses **Create key**. Give it a name, the scopes it needs, an expiry and a rate limit. The key is shown once; copy it into your secrets manager or CI secrets. See [Authentication](/api/authentication).

</Step>
<Step>

### Call `GET /api/me`

It answers with the key itself, so it is the quickest way to check a key works.

<Tabs items={['cURL', 'TypeScript', 'Python']}>
<Tab value="cURL">

```bash
curl https://api.coderhelm.com/api/me \
  -H "Authorization: Bearer $CODERHELM_API_KEY"
```

</Tab>
<Tab value="TypeScript">

```ts
const res = await fetch('https://api.coderhelm.com/api/me', {
  headers: { Authorization: `Bearer ${process.env.CODERHELM_API_KEY}` },
});
if (!res.ok) throw new Error((await res.json()).error);
const me = await res.json();
console.log(me.api_key.name, me.capabilities);
```

</Tab>
<Tab value="Python">

```python
import os
import requests

res = requests.get(
    "https://api.coderhelm.com/api/me",
    headers={"Authorization": f"Bearer {os.environ['CODERHELM_API_KEY']}"},
)
res.raise_for_status()
me = res.json()
print(me["api_key"]["name"], me["capabilities"])
```

## What you can call

| Resource | Endpoints | Scope to change things |
| --- | --- | --- |
| Account | Get the caller | |
| Runs | List runs, get a run, retry a run, cancel a run | `runs` |
| Plans | List plans, create a plan, get a plan, approve and run a plan | `plans` |
| Repositories | List repositories | |
| Reviews | List reviews, get a review | |
| Usage | Get this month's usage | |
| CI | Upload a test report, list quarantined tests | GitHub Actions OIDC token, no key |
| Webhooks | GitHub, Jira and AWS SNS events CoderHelm receives | Verified by signature |

Reading needs only the `view` scope, which every key has.

Everything else the dashboard does goes through routes that are not part of this API. They can change at any time, and an API key that calls one gets `403` with the code `not_available_to_api_keys`.

## Requests and responses

- **Times** are RFC 3339 strings in UTC, such as `2026-10-22T14:03:11Z`.
- **Ids** are strings. Run, plan and task ids are ULIDs: newer ones sort after older ones.
- **Missing values** are `null`. A field documented as nullable is always present.
- **New fields** can appear in responses at any time. Ignore the ones you don't know. See [Versioning](/api/versioning).
- **Errors** always have a JSON body with `error` and `code`. See [Errors](/api/errors).
- **Lists** that can grow are paged with a cursor. See [Pagination](/api/pagination).
- **Rate limits** are per key, and every answer says where you stand. See [Rate limits](/api/rate-limits).

## OpenAPI document and Markdown

The whole API is described by an OpenAPI 3.1 document, generated from the gateway's code so it always matches it:

- [`https://docs.coderhelm.com/openapi.json`](/openapi.json), published with these docs
- `https://api.coderhelm.com/openapi.json`, served by the API itself

Load it into Postman, Insomnia, an SDK generator or your own tooling. Every page here, endpoints included, also has a Markdown version (add `.md` to its address), and [`/llms.txt`](/llms.txt) lists them all for AI assistants.

## No try-it console

The reference has no in-browser console. The API accepts browser requests only from the dashboard, so a console on this site would need your key to pass through a proxy. Every endpoint page shows copyable requests instead, which you can run from a terminal with your key in `CODERHELM_API_KEY`.
