Settings are the values that differ between teams. You declare them in the manifest; each team fills them in on the install screen. Values live in the team's settings, never in the plugin.

```yaml
settings:
  - key: brand_voice_doc
    type: text
    label: Brand voice
    description: Paste your voice and tone guide.
    required: true
  - key: tone
    type: select
    options: [friendly, formal]
    default: friendly
  - key: crm_api_key
    type: secret
    label: CRM API key
  - key: linkedin
    type: connection
    provider: oauth2
    scopes: [w_member_social]
```

## Types

| Type | Shows as | Notes |
| --- | --- | --- |
| `string` | One line | |
| `text` | A text box | Brand guides, templates. |
| `number` | A number | |
| `boolean` | A switch | |
| `select` | A choice | Needs `options`. |
| `secret` | A hidden field | Sealed, never shown again, never given to a model. No `default`. |
| `connection` | A **Connect** button | An outside account; see [Connections and OAuth](/plugins/connections). Needs `provider`. No `default`. |

Every field is in the [manifest reference](/plugins/manifest-reference#settings).

## Where settings reach

- **In instructions**: agents see the values of non-sensitive settings (for example the brand guide) as part of their context.
- **In tools**: a defined tool can use `{settings.key}` in its URL, headers or body. Values are filled in after the model has chosen the call, so even non-sensitive settings used this way are not something the model can change.
- **Never**: a `secret`, a `connection` or any setting with `sensitive: true` is never put in a prompt, never returned by the API and never logged. Like other CoderHelm keys, it is encrypted with AWS KMS with the team and plugin bound into the encryption, and opened only for the call that needs it.

## Required settings

A plugin with an empty `required` setting is installed but can't run. The install screen says which values are missing.
