---
title: Test a plugin locally
description: Check plugin.yaml, your skills and your agents with the validator before you push.
---


The validator checks a plugin folder the way CoderHelm will when you install it. It needs only Node.js 20 or newer.

```bash
curl -fsSLO https://docs.coderhelm.com/tools/validate-plugin.mjs
node validate-plugin.mjs path/to/your-plugin
```

The file is a single script with its dependencies bundled in. It is built from the same [JSON Schema](/plugins/manifest-reference) this site publishes, on every build of these docs.

## What it checks

The same checks CoderHelm makes when it reads a plugin:

1. `plugin.yaml` (or `plugin.yml`, or `.coderhelm/plugin.yaml`) against the manifest schema: required fields, types, allowed values, and no unknown fields (a typo fails instead of being ignored).
2. Every `skills` and `agents` glob matches at least one file, and every file fits the limits (64,000 bytes per skill or agent; 200 items; 2,000,000 bytes in all).
3. Each agent's `tools:` are granted in `plugin.yaml`, and no named tool clashes with one allowed from a connection.
4. A connection's `allow` list is never `*`.
5. An HTTP tool names a `connection` setting, calls an `https` address, sends no credential headers, and its `body` only uses `{{setting:<key>}}` for string settings that aren't sensitive.
6. A `publish` output goes through a tool that works out as `consequential`.
7. `results` reads through an `mcp:` server the plugin lists, with a read-only tool.

## Output

```txt
$ node validate-plugin.mjs ./marketing
ok       marketing 1.0.0
```

```txt
$ node validate-plugin.mjs ./broken
error    tools.publish_post: the body uses setting `linkedin`, which must be a string setting that isn't sensitive
error    agents/rogue.md: tool `delete_document` is not granted in plugin.yaml `tools`

2 errors: the plugin would be refused.
```

It exits with status 1 when there are errors, so it can run in CI:

```yaml title=".github/workflows/plugin.yml"
name: Plugin
on: [push, pull_request]
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: curl -fsSLO https://docs.coderhelm.com/tools/validate-plugin.mjs
      - run: node validate-plugin.mjs .
```

## Editor checks

Point your editor at the schema for completion and inline errors as you type. With the YAML extension for VS Code, start `plugin.yaml` with:

```yaml
# yaml-language-server: $schema=https://docs.coderhelm.com/schema/plugin-manifest.v1.json
```

## Try it on a test team

The validator checks the package; only a run checks the behavior. Add your repository as a source on a test team, follow your working branch, install the plugin, start it with a brief, and read the run and its drafts. Nothing can be published without an approval, so a test run is safe.
