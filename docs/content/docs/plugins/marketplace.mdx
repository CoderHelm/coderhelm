---
title: Private marketplace
description: Give your team a catalog of approved plugins from your own git repository.
---


A private marketplace is a plugin source with several plugins in it: one repository, one `plugins/<name>/` folder per plugin, each folder with its own `plugin.yaml`.

```txt
your-org/coderhelm-plugins
└── plugins/
    ├── marketing/
    │   └── plugin.yaml
    ├── support-replies/
    │   └── plugin.yaml
    └── sales-notes/
        └── plugin.yaml
```

Each source is read at a pinned commit. A private source is read only through your team's own GitHub App installation, so no other team can read it.

Make the repository private and readable by your team's GitHub App, then add it as a source on the **Plugins** page as `your-org/coderhelm-plugins`. Its plugins appear in the catalog on the **Plugins** page, and installing one goes through the usual steps: an admin installs, a second admin approves when there are two, and connections are made separately.

## Keep it vetted

- Protect the repository's default branch and require review, since merging is publishing.
- Run the [validator](/plugins/testing) in the repository's CI for every folder.
- Have the source follow a release branch or a tag, not your working branch.
- Keep each plugin's team-specific values in settings.
