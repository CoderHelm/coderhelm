In this walkthrough you build a plugin that:

- reads each new release (and a weekly schedule, and briefs from people),
- drafts a blog post in your CMS, three LinkedIn posts and an email, in your brand voice,
- waits for an editor to approve a post, then publishes it to LinkedIn at the time they pick.

The finished plugin is in the docs repository at [`docs/examples/marketing`](https://github.com/CoderHelm/coderhelm/tree/main/docs/examples/marketing). The files on this page are included from it, and the docs' tests validate it on every build, so what you read here is what passes.

### Create the repo

```bash
mkdir marketing-plugin && cd marketing-plugin
git init
mkdir -p skills/brand-voice skills/launch-checklist agents
```

</Step>

<Step>

### Write the manifest

Now declare everything the plugin needs.

<include meta='title="plugin.yaml"'>../../../examples/marketing/plugin.yaml</include>

Section by section:

- **settings**: the brand guide and banned claims are text the agent reads. `sanity` and `linkedin` are accounts the team connects; `linkedin_org` says which company page to post as.
- **tools**: from Sanity, only three tools, at `write` risk because drafts there are not public. `publish_post` is the plugin's own tool: one LinkedIn API call, `consequential` because it reaches the public. Its token comes from the `linkedin` connection and never reaches the model.
- **triggers**: every release, Mondays at 10:00 New York time, and a brief form.
- **outputs**: three kinds of draft, and publishing through `publish_post` once one `marketing_editor` approves.
- **budget**: at most 2 million new tokens a month.

</Step>
<Step>

### Validate

```bash
curl -fsSLO https://docs.coderhelm.com/tools/validate-plugin.mjs
node validate-plugin.mjs .
```

```txt
ok       marketing 1.0.0
```

Try breaking it: change `publish_post`'s `risk` to `write` and the validator refuses, because a publish output must go through a consequential tool. Add `delete_document` to the agent's `tools:` and it refuses again, because the manifest doesn't grant it.

</Step>
<Step>

### Push and install

Push the repo to GitHub. In CoderHelm, an admin installs it by `owner/name`; with two admins, the second approves. Then the team:

1. fills in **Brand voice**, **Claims we never make** and **LinkedIn organization id**,
2. connects Sanity (on Connections) and LinkedIn (the **Connect** button),
3. creates the `marketing_editor` approver group and adds the editors.

</Step>
<Step>

### Run it

Start it by hand first: open the plugin, fill in the brief ("Announce the new export button") and pick channels. Or publish a release on a connected repository.

The run reads the release notes and merged pull requests, checks earlier posts in Sanity, and saves the drafts. A card goes to the team's Slack or Teams channel.

</Step>
<Step>

### Approve and publish

An editor (not the person who asked) opens the review queue, edits one LinkedIn variant, and approves it for Tuesday at 10:00. On Tuesday, CoderHelm calls `publish_post` with exactly the approved text. Until then, anyone can cancel. The audit log records the trigger, the plugin version, the agent's tool calls, the editor's approval and the result.

</Step>
</Steps>
